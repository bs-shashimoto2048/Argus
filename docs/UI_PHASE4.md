# UI再設計 Phase 4: 共通レイアウト・Dashboard・履歴・データ保存設定

Phase 1〜3（`reading_records` / 記録画像 / Excel出力）のAPIを使う画面です。**Backendの変更はありません**。

## 画面とルート

| ルート | 画面 |
|---|---|
| `/` | ダッシュボード: 状態サマリー（正常/要確認/通信異常）、Monitorカード、下部に「計測履歴」（今日、20件/頁） |
| `/monitors` | モニター管理: 一覧（状態・engine・model・現在値）、詳細へ、新規モニター |
| `/monitors/new`, `/monitors/:id` | 既存（Phase 5で再編予定）。共通レイアウト内で表示し、戻る導線は`/monitors` |
| `/history` | 履歴・データ: Monitor複数選択、今日/過去7日/任意期間、ページネーション（50件/頁）、Excel出力 |
| `/settings` | システム設定: 「データ保存」（画像保存先・Excel保存先・保存ON/OFF・容量しきい値・保存状態・書込みテスト） |

全画面に共通の上部ナビゲーション（`ARGUS 遠方監視システム` / ダッシュボード / モニター管理 / 履歴・データ / システム設定）があります（`AppLayout`）。ユーザー表示は、現状のArgusにユーザー認証が無いため設けていません。

## 履歴の表示規則

- 期間はJST。APIの`to`は排他的なので、UIで終了日に`2026-10-09`を指定した場合は`2026-10-10T00:00:00+09:00`を渡します（Backendは補正しない）。今日=当日0:00〜翌0:00、過去7日=今日を含む7暦日。
- 確定値は記録の`value`（先頭0除去後の正式値）をそのまま表示します。
- 状態は運用者向けに変換して表示します（優先順位: 通信異常・停止中 > 基準値競合 > 読取異常 > 前回確定値を保持 > 値なし > 要確認 > 正常）。元値（`display_status` / `validation_status` / `value_source` / `baseline_conflict`）は詳細Drawerで確認できます。
- `value_source=carried_forward`の行は強調（左の色帯＋背景）し、棄却された最新Rawを確定値の下に併記します。Rawの取りこぼしが続いている状況（同じMonitorで連続）に気付きやすくするためで、連続時間の集計は未実装です。
- ダッシュボードのMonitorカードは、そのMonitorの最新の1時間記録が`carried_forward`の場合に「前回確定値を保持」（記録時刻・Raw・validation_status）を補助表示します。大きな現在値は常に正式値です。

## 記録画像Drawer

履歴行の「画像」「詳細」で右Drawerを開きます。`GET /api/records/{id}/image/{original|overlay}`の**保存済み画像だけ**を表示し、現在のlive映像は使いません。画像が無い記録は、`image_status`に応じて「記録画像なし」「保存に失敗しました」「保存しませんでした」「画像保存が無効でした」等を表示します（壊れた画像アイコンは出しません）。ファイル欠損・保存先の変更で読み込めない場合も説明を表示します。

## Excel出力

履歴・データ画面の「Excel出力」から、現在のMonitor/期間フィルタをそのまま`POST /api/records/export/excel`へ渡します。方式は「ダウンロード」または「サーバー保存」（`save_to_server=true`）です。サーバー保存では、ファイル名・保存先・行数・シート数を表示します。422/404/409/503は運用者向けの文言に変換して表示します。

## データ保存設定

- `GET/PUT /api/system/data-storage`、`GET .../status`、`POST .../test`を使います。保存先は絶対パス（ローカル/UNC）の文字入力で、フォルダpickerはありません。「書込みテスト」は画像保存先・Excel保存先それぞれにあり、入力中のパス（空欄なら既定の保存先）を試します。
- **画像保存先を変更して保存する場合は、保存前に確認ダイアログを表示します**（DBには画像保存先からの相対パスだけを保存しているため、旧保存先の画像は履歴画面で参照できなくなる）。Excel保存先の変更では表示しません。
- 保存状態: state（正常/警告/保存停止/保存先異常/保存無効）、空き容量、しきい値、画像保存Worker、待ちキュー、サーキット、保存失敗/見送り件数。

## 既知の制約

- 画像保存先の変更後に旧画像を参照できない課題は残っています（将来、記録時のstorage rootを保持する方式を検討）。
- Monitorカードに「単位」は表示しません（Monitorに単位の設定項目が無いため）。
- Monitor Detailの再編（タブ化・baseline操作等の整理）はPhase 5です。

> Phase 5で、履歴のMonitor選択はプルダウン（1台または「すべて」）、期間は3択（任意期間のときだけ期間選択BOX）に変更し、履歴表をヘッダー固定のスクロール式にしました。Monitor Detailのタブ化と`/api/cameras`の遅延取得も同Phaseです（`docs/UI_PHASE5.md`）。
