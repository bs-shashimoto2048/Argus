# UI再設計 Phase 5: Monitor Detailのタブ化・履歴UIの操作改善・画面揺れ防止

**Backendの変更はありません**（Frontendのみ）。推論・Reading・baselineのロジックにも触れていません。

## 計測履歴UI（Dashboard下部 / 履歴・データ / Monitor DetailのHistoryタブ）

- **Monitorはプルダウン**（「すべてのモニター」または1台）。変更した瞬間に履歴を再取得します（「適用」ボタンなし）。Excel出力は現在のフィルタをそのまま使うので、複数Monitorをまとめたい場合は「すべてのモニター」を使います。
- **表示期間は3択**: 今日 / 過去7日 / 任意期間（選択中のボタンは強調表示）。選択した瞬間に切り替わります。
- **任意期間のときだけ**期間選択BOX（開始日 ～ 終了日）を表示します。開始日・終了日が有効（開始≦終了）になった時点で即時に更新します。APIの`to`は排他的なままで、UIの終了日`2026/08/26`は`2026-08-27T00:00:00+09:00`として渡します（Backendは補正しません）。
- **履歴表はヘッダー固定のスクロール式**: 1つの`table`（`table-layout: auto` + 全セル`white-space: nowrap`、表は内容幅`width: max-content`で、余った幅をモニター名などの列へ配らない）の中でヘッダーを`position: sticky`にして固定し、表の中だけが縦スクロールします。列位置はずれず（`scrollbar-gutter: stable`）、狭い画面では表の内部だけが横スクロールします（ページ全体の横スクロールなし）。表のエリアは常に同じ高さです（Dashboardは固定、履歴・データ画面は画面の高さに合わせる）。読込中・0件・多数件でも高さが変わりません。

## Dashboard

- ページタイトル「ダッシュボード」は置きません（上部ナビゲーションにあるため）。
- **[＋ モニター追加]の右隣に、同じ操作グループとして Monitoring 表示**（`● Monitoring | 5 FPS | ⚙`）を置きます。両者は同じ高さ（40px）・角丸（8px）・フォントサイズで、Monitoringは白地の枠線つきコンパクトコントロール（操作ボタンではなく状態表示なので、色は青ではなく白）。●は稼働中のMonitorがあれば緑、FPSは現在の表示FPS設定、⚙は既存のDashboard設定です。hover / focusの表現も揃えています。

## Dashboardの縦並び（カード → 使用量推移グラフ → 計測履歴）

- **Monitorカード**: 1行に最大3枚（3列固定）。1〜3台は1行、4台以上は3列のままカード領域（`.monitor-region`、最大高さ`clamp(240px, 36vh, 420px)`）の中だけが縦スクロールし、ページはMonitor台数で伸びません。表示順は`display_order`のまま（異常なMonitorを前へ出しません）。4台以上では「3 / 7台表示」（見えているカード数 / 全台数）をツールバーに表示します。
- **使用量推移グラフ**（`TrendChart`、SVG手描き・外部ライブラリなし、高さ180px）: 既定は使用量、[使用量][累積値]（累積値=正式値`value`の系列）で切替。Monitorごとに1本の折れ線（色分け・凡例・ホバーで値）。使用量がnullの点は線を途切れさせます（補間しない）。データは`GET /api/records`（履歴と同じMonitor・期間、limit=1000でページを進めて期間内の全件、最大20,000件）。
- **条件の共有**: Monitor・期間のコントロールは計測履歴ヘッダーに1組だけあり、グラフも同じ条件（`DashboardPage`が状態を保持）で描画します。
- **イベント構造**: `ChartEvent`（`kind`: `carried_forward` / `baseline_conflict` / `manual_corrected`、`monitor_id`、`time`、`label`）を記録のフィールドから抽出し（`utils/trend.ts`）、`TrendChart`の`renderEvent`で印を描画します。既定は前回値保持（ひし形）・手動修正（二重丸）のみで、基準値競合は構造だけ用意（未描画）です。
- **[Export (XL)]**（計測履歴ヘッダー、期間コントロールの右隣）: 現在のMonitor・期間に該当する**全件**（段階読み込み前の行を含む）を、常に.xlsxで出力します（`POST /api/records/export/excel`、`save_to_server=false`。1ブック・Monitorごとに1シート、シート名=モニター名（31文字・禁止文字置換・重複はMonitor ID付与）、`display_order`順）。保存先はブラウザの`showSaveFilePicker`（File System Access API）が使えれば保存ダイアログ（提案名`argus_records_YYYYMMDD_YYYYMMDD.xlsx`）、無ければ通常のダウンロードです。ダイアログのキャンセルは何も表示せず、失敗はエラー表示します。行数の上限はAPI側にありません（Excelの1シート上限1,048,576行のみ）。

## 画面揺れ防止

- `html { scrollbar-gutter: stable }`（scrollbarの出現・消滅で横にずれない）、`body { overflow-x: hidden }`。
- 数値（確定値・Raw・信頼度・使用量等）は`font-variant-numeric: tabular-nums`。
- Monitorカードは、通知欄（前回確定値を保持・基準値conflictのバッジ）の高さを常に確保し、値の桁数・バッジの有無・状態で高さが変わりません。ライブ画像は固定高さ、Drawerの記録画像は`aspect-ratio: 16 / 9`で、読込前後でサイズが変わりません。
- 実ブラウザ（1366×768 / 1920×1080）で、30秒間の更新中のlayout shiftは0、カード高さ・履歴領域の高さ・ページ幅は不変であることを確認しています。

## Monitor Detail（`/monitors/:id`）のタブ

`?tab=history|settings|diagnostics`で直接開けます（既定はMonitoring）。編集中のSettingsの入力値は、タブを切り替えても失われません。

| タブ | 内容 |
|---|---|
| **Monitoring** | 日常監視用。ライブ画像/推論オーバーレイ、確定値・前回値・信頼度・状態、Raw（最新・未確定）、engine、model、最終更新、baseline、conflict、警告。**危険な設定操作は置きません** |
| **History** | このMonitorの計測履歴（Monitor選択なし、今日/過去7日/任意期間、記録画像Drawer）。Dashboard/履歴画面と同じコンポーネント |
| **Settings** | 基本情報、映像Source、推論Engine/Model、前処理、ROI、読取安定化（Reading settings）、保存、Danger Zone（削除）。既存の機能・保存処理はそのまま |
| **Diagnostics** | 技術確認用。Engine/Model・映像Runtime・映像取得fps・推論エラー、推論オーバーレイ、推論入力、Raw・検証・基準値・合意候補・conflict、Pipeline診断。末尾に**「管理操作」**（読取基準値の再設定/リセット）を通常の設定と分けて配置 |

## baseline の reset / rebase（管理操作）

Diagnosticsタブの「管理操作」にあります。**再設定（rebase）は確認ダイアログ**で、現在の基準値・最新のRaw・合意候補・指定する値・理由・操作者を確認してから実行します。Backendのforce要求（最新のRaw合意値と大きく異なる値）・入力検証・監査履歴は変更していません。

## /api/cameras

- 以前は、Monitor Detailを開くだけで`SourceSettings`が`/api/cameras`を呼んでいました。**現在は呼びません**（どのタブを開いても0回）。
- 現在設定されているsourceは、カメラ検出なしで表示されます（「現在の設定: Camera N」/ URL）。
- 検出できるカメラ一覧は、「カメラ選択（検出）」「再スキャン」を押したときだけ取得します。検出に失敗しても現在の設定は保持されます。

## Monitor表示順の並べ替え（追加仕様）

Dashboardのカードの順番を、**モニター管理（`/monitors`）から変更して永続化**できます。

- **DB**: `monitors.display_order`（整数）。既存Monitorは起動時にid昇順の順位（id=2,3,4 → 0,1,2）で補完（設定済みの値は変更しない）。新規Monitorは末尾（最大+1）。削除による欠番は詰め直しません。
- **一覧の順序**: `GET /api/monitors`は`display_order ASC → id ASC`（未設定は最後）。Dashboard・モニター管理・履歴のMonitor選択は、APIの順序をそのまま使います（Frontendで独自にソートしない）。Excelのworksheet順も現在の表示順に揃います（値・意味は変更なし）。
- **API**: `PUT /api/monitors/order`（`{"monitor_ids": [4, 2, 3]}`）。重複ID・存在しないIDを拒否し、全Monitorの指定を必須とし、**1 transaction**で更新します（`docs/06_API_REFERENCE.md`）。
- **UI**: 各行の**右端の三本線（☰）をドラッグ&ドロップ**して並べ替えます（↑↓ボタンはありません。行全体はドラッグさせないので、「詳細へ」等のクリックと競合しません。cursorは grab / grabbing、hoverとdrag中は強調）。**drop完了時に自動保存**します（保存ボタンなし）。保存中は「保存中...」、成功すると短時間「保存済み」。保存中は楽観的に新しい順を表示し、**失敗したときは元の順へ戻して**エラーを表示します（一覧が更新されていた場合は再読み込みして同期）。定期更新の結果で保存中の順序が一瞬戻ることはありません。
- 履歴データ（`reading_records`等）は変更しません。表示順は現在のUI表示順だけの設定です。

## Monitor Detail の画面密度・日本語表記・ナビゲーション（追加修正）

- **タブ名は日本語**: 監視 / 履歴 / 設定 / 診断（URLの`?tab=monitoring|history|settings|diagnostics`は従来のまま）。項目名・見出しも日本語にし、内部値（`cpp_onnx` / `decrease_detected` / `carried_forward` 等）は原文のまま表示します（例: 読取判定 `decrease_detected`、値の由来 `前回確定値を保持(carried_forward)`）。設定タブの見出しは「映像ソース」「推論エンジン / モデル」「前処理」「読取安定化設定」「危険な操作」。
- **監視タブ**: 左に映像（16:9固定・高さは`clamp(300px, 46vh, 520px)`に制限・横幅も制限）、右に現在値・前回値・信頼度・状態と、最新推論値（未確定）・推論エンジン・モデル・最終更新・読取基準値・基準値競合のコンパクトなカード。警告は右カラム最下部に置き、上の要点の位置を動かしません。映像の切替・読込でも枠の高さは変わりません。1366×768・1920×1080ともに、縦スクロールなしで主要情報が収まります。
- **診断タブ**: 2〜3列のコンパクトなカード（稼働状態 / 推論エンジン・モデル / 推論の状態 / 読取判定 / 読取基準値 / 基準値競合 / 推論入力画像 / 推論オーバーレイ）。画像の枠は16:9・高さ上限つき。詳細（推論Pipeline診断・管理操作）はアコーディオン（既定は閉）。
- 旧レイアウトの「ページを`100vh`に固定して内部スクロールさせる」ルールは、タブ化後は設定・診断タブの下部を隠してしまうため廃止しました。
- **上部ナビゲーション**: 左に「ARGUS 遠方監視システム」、右にメニュー4項目（右寄せ）。狭い幅では折り返し（重ならない）。ダークヘッダー・activeの下線・hover・focusは維持。

## Dashboard / 計測履歴のコンパクト化（追加修正）

- **状態サマリー**: 縦長のカードをやめ、`正常 3` `要確認 0` `通信異常 0` の**横長chip（高さ34px、同一高さ）**を1行に並べます（緑 / 黄 / 赤）。右側の[＋ モニター追加]とMonitoringは従来どおり同じ行です（toolbar全体の高さは40px）。
- **計測履歴のヘッダー**: 左に「計測履歴」と説明、**右にMonitorプルダウン・今日/過去7日/任意期間（任意期間のときだけdate range）を同じ行**に置きます（履歴・データ画面ではExcel出力も同じグループ）。フィルタ専用の2行目はありません。幅が足りないときだけ折り返します。
- **ページ送りを廃止**（Dashboard・履歴・データ・Monitor Detailの履歴タブ）。前へ/次へ/ページ番号はなく、現在の条件の**全件を、固定ヘッダーの1つのスクロール領域で縦スクロールだけで確認**できます。表の高さはviewport基準（Dashboardは`clamp(340px, 54vh, 660px)`、履歴・データは画面に合わせる）で固定です。
- **段階的な読み込み（incremental loading）**: 初回は先頭500件だけ取得し、スクロールが末尾に近づいたら次の500件（`offset=500, 1000, …`）を追加取得します（全件を一度に取得しません）。追加取得中の二重リクエストは行いません。件数は表の下に「`1,200件中 500件を表示（下へスクロールで続きを読み込みます）`」「`42件（全件表示）`」と表示します。Monitor/期間を変えると即時に先頭から取り直します。60秒ごとの更新は、新しい記録（先頭側）だけを軽く取得して差し込み、読み込み済みの行とスクロール位置を保ちます。
- **Dashboard全体はviewport内に収まります**: ルートは「`100dvh` − 上部ナビ（`--nav-h`）」の縦flexで、状態サマリー・Monitorカードは固定サイズ（`flex: 0 0 auto`）、計測履歴のsectionが**残り高さ**（`flex: 1 1 auto; min-height: 0`）を使い、表の容器だけが`overflow-y: auto`で内部スクロールします（`overflow: hidden`で切っていません）。Monitorカードは情報（画像・現在値・信頼度・更新・取得状態・バッジ）を残したまま高さを詰め、3枚とも同じ高さです。1366×768でもページ全体の縦スクロールは出ません（内容がこの高さに収まらない小さな画面では、内部で潰さずページ側がスクロールします）。
- Backend APIのpagination仕様（`limit`/`offset`）は変更していません。

## 計測履歴の視認性・設定タブの整理・リアルタイム時計（追加修正）

- **リアルタイム時計**（全画面共通の上部ナビ）: ロゴ「ARGUS 遠方監視システム」の右隣に `YYYY/MM/DD HH:mm:ss JST`（24時間表記、Asia/Tokyo基準）を表示します。Frontendで1秒ごとに更新し、Backend APIは呼びません。ロゴより小さく薄い色（`#94a3b8`）で背景なし・左に細いseparator、`tabular-nums` と固定幅（`min-width`）で秒更新でもナビの位置が揺れません。狭い幅（〜1100px / 〜900px）ではfont・gapを縮小し、800pxでも重なり・横スクロールはありません。右側のメニューの位置は変えていません。
- **使用量の欠損表示**: `usage` が null のときは「`-`」（`0.0` は `0.0`、`0` は `0` のまま）。UI表示だけの変更で、DB/APIの値は変えていません（前回値などの欠損は従来どおり「--」）。
- **縦罫線**（ヘッダー・本文）: 通常の列境界は `1px solid #d7dde7`。データ列群の境界（「確定値」の左＝モニター情報→数値データ、「状態」の左＝数値→状態・操作）は `2px solid #c3cad5`。
- **数値列の色分け**: 確定値 `#1d4ed8` / 前回値 `#475569` / 使用量 `#0f766e` / 信頼度 `#15803d` / carried_forwardのRaw補助 `#b45309`（状態badgeの色は従来どおり）。数値4列は右寄せ・`tabular-nums`。
- **時刻グループ**（「すべてのモニター」のときだけ）: 同じ計測枠（`hour_bucket`）の行を1グループとして、時刻の新しい順 → 同一時刻内はMonitorの表示順（`display_order`）に並べ、グループごとに交互の薄い背景（`#ffffff` / `#f7fafc`）、時刻が変わる先頭行に強めの上罫線（`2px solid #cbd5e1`）を付けます。**状態による背景強調（carried_forward・基準値競合・通信異常・読取異常・warning）はグループ背景より優先**されます。Monitorを1台だけ選択している場合は、交互背景と時刻の区切りは付けません（縦罫線・数値の色分け・状態の強調は維持）。
- **Monitor Detail「設定」タブ**: 2カラム（左=基本情報・映像ソース・ROI・前処理 / 右=推論エンジン / モデル・読取安定化設定・保存・危険な操作）。各セクションは折りたたみ式で、**閉じていても現在値の概要**が見出しの右に表示されます（例: 読取安定化設定「有効 / majority / 3一致 / 単調増加」、ROI「幅50% × 高さ25%」、前処理「3項目を設定」）。既定で開くのは基本情報・映像ソース・推論エンジン / モデルで、前処理・ROI・読取安定化設定・危険な操作は閉じています。基本情報は内部名・表示名・設置場所を1行（3列）に、映像ソース・推論エンジン / モデルの本文は2列gridにして縦を詰めました（設定項目・保存処理は変更なし）。**危険な操作（管理操作）は保存ボタンと別の領域**（区切り線の下、既定で閉）にあります。1366×768でもページ全体の縦スクロールなしに収まります（変更前は約1.8画面分）。

## 既知の制約

- 診断の「processing time（推論処理時間）」は、Backendのdiagnostics APIが返していないため表示していません（映像取得fps・最新フレーム経過秒は表示）。
- Monitorカードの「単位」は、Monitorに単位の設定項目が無いため表示していません。
- carried_forwardの連続時間の集計は未実装です。
- 履歴は読み込んだ行をすべてDOMに描画します（数万行まで読み進めると重くなる可能性があります。必要になれば仮想スクロールを検討）。
- 画像保存先の変更後に旧画像を参照できない課題は残っています（Phase 4で警告を追加済み）。
