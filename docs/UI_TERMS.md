# 利用者向けUIの用語

通常のUIには、内部実装名（`decrease_detected` / `carried_forward` / `baseline` / `rebase` / `reset` / `Raw` / `epoch` など）を出さず、
次の用語で統一する。API・DB・変数名は変更しない。文言は `frontend/src/utils/readingLabels.ts` に集約している（Componentごとに持たない）。
診断タブなど技術者向けの画面では、日本語の後ろに内部名を括弧で併記してよい（例: `読取基準値より小さいため不採用（decrease_detected）`）。

| 内部名 | 通常UIの表示 | 説明（例） |
|---|---|---|
| Raw / 最新推論値 | 最新のAI読取値 | AIが画像から読み取った最新値です。正式値として採用される前の候補値を含みます。 |
| 確定値 / 正式確定値 | 正式値 | 履歴・使用量計算に使用する値です。 |
| baseline | 読取基準値 | 積算値の減少チェックを行う際に、AI読取値と比較する基準となる値です。 |
| baseline conflict | 読取基準値との不一致（バッジ: 基準値と不一致） | AI読取値が現在の読取基準値と矛盾しているため、正式値として採用していません。 |
| rebase | 読取基準値を指定値へ変更 | 現在の読取基準値を、運用者が確認した値へ変更します。 |
| reset | 読取基準値を未設定に戻す | 現在の読取基準値を解除し、次に正常確定したAI読取値を新しい読取基準値として設定します。 |
| monotonic | 積算値の減少チェック | AI読取値が現在の読取基準値より小さい場合、正式値として採用しません。 |
| carried_forward | 直前の正式値を継続使用 | AI読取値が採用されなかったため、直前まで使用していた正式値をこの記録でも使用しています。 |
| value_source | 正式値の決まり方 | 今回のAI読取値を採用 / 直前の正式値を継続使用 / 正式値なし / 運用者が確認・修正 |
| 手動修正 | 運用者修正（運用者が確認・修正） | AI読取値・信頼度・画像などの記録時証跡は変更されません。 |
| majority / consecutive | 多数決 / 連続一致 | 直近の読取結果の中で最も多く一致した値を採用 / 同じ値が指定回数連続した場合に採用 |
| window_size | 判定に使う直近読取回数 | 直近N回のAI読取結果を使って値を判定します。 |
| required_matches | 採用に必要な一致回数 | 同じ値が指定回数以上確認された場合に採用します。 |
| min_confidence | 採用に必要な最低信頼度 | 0〜1で指定（0.6 = 60%）。 |
| expected_digits | メーターの表示桁数 | AIが読み取る数字の桁数です。異なる桁数の読取値は採用しません。 |
| decimal_position | 小数部の桁数 | 右端から何桁を小数として扱うかを指定します（例: 1 → 3724644 を 372464.4）。 |
| max_rate_per_minute | 1分あたりの最大増加量 | これを超える急な増加は、誤読の可能性があるため採用しません。制限なしの場合はこのチェックを行いません。 |
| max_consecutive_failures | 読取不能と判定するまでの連続失敗回数 | AIが連続してこの回数読み取れなかった場合、読取不能として扱います。 |
| Rollover | 最大値から0へ戻るメーターを許可 | 桁が最大値まで進んだあと、0へ戻るタイプのメーターで使用します。 |
| epoch | （通常UIでは非表示） | 診断タブでは「基準値世代（内部管理番号）」 |

## AI読取結果（validation_status）

| 内部名 | 表示 |
|---|---|
| confirmed | 採用 |
| low_confidence | 信頼度が低いため要確認 |
| decrease_detected | 読取基準値より小さいため不採用 |
| rate_exceeded | 増加量が設定上限を超えたため不採用 |
| invalid_format | 表示桁数・小数部の形式が一致しないため不採用 |
| no_reading | 読取値を取得できません |
| pending | 判定中 |
| （未知） | 判定状態を確認してください |

不採用の理由は、記録の詳細・読取値修正ダイアログで「今回のAI読取値『…』は…採用されませんでした。そのため、直前の正式値を継続使用しています。」の形で説明する。

## 読取基準値の変更・未設定化

「設定」タブ →「読取安定化設定」→「積算値チェック」から、現在の読取基準値の確認、[基準値を変更]、[基準値を未設定に戻す]ができる（理由・操作者が必須。監査履歴に残る）。
最新のAI読取値から大きく離れた値は「入力した基準値は、最新のAI読取値から大きく離れています。桁数・小数点位置・実メーターの表示を確認してください。」の確認（戻る / 確認して変更）を経て変更する。
内部のAPIは既存の rebase / reset を使う。診断タブの「読取基準値」パネルからも同じ操作ができる。

## APIエラーの表示

`CORRECTION_FORCE_REQUIRED` / `REBASE_FORCE_REQUIRED` / `NO_CHANGE` / `INVALID_VALUE` / `NOT_CORRECTABLE` などの内部codeは画面に出さない（日本語のメッセージのみ。codeはconsoleへ）。
